# 视觉导演 Visual Director

文案定稿之后、写任何 HyperFrames 场景之前，先让一个"视觉导演"把整条片子的画面设计出来。导演只管"画面演什么、怎么演"，不写代码；HyperFrames 那一步只负责照着方案实现。

为什么要单独一步：边写代码边想画面，agent 会挑最省事的做法，结果就是动画少、全是字卡、一股模板味。先设计、再实现，是动画和广告行业的标准流程（分镜 / animatic 先于制作）。

## 什么时候做、谁来做

- **时机**：文案（逐句稿）被创作者确认之后，配音和做素材之前。文案改动较大时，重做一次。
- **谁来做**：最好开一个独立的 agent（子 agent）来当导演，只给它文案、风格选择和素材清单，让它不受前面写代码思路的影响。客户端不支持子 agent 时，就在当前会话里明确切换成"导演"角色，按本页一步步做完再回来。
- **产出**：项目里的 `VISUAL.md`（视觉方案），以及两三张风格帧或一个可以播放的开场预览。

## 第一步：先问用户有没有想要的风格

只问一次，问清楚就行：

- 有没有想要的风格或参考？（截图、别人的视频、STYLE-SHEET.md 里的某一种）
- 有没有一定要有、或者一定不要的东西？（出不出镜、要不要搞笑、要不要真实录屏）

**用户有想法** → 在用户给的风格里做设计，不换风格，只把演法做足。
**用户没想法或说"你定"** → 导演自己提方案（第三步），并在 HANDOFF.md 里记下"风格由导演提议、用户选定"。

## 第二步：读稿，盘点

1. **给每一句标节拍**：钩子、介绍、列要点、揭晓、反转、章节切换、金句、讲步骤、成长、讲错误、做选择、揭示全貌、情绪……（节拍表见 [staging.md](staging.md) 第六节）。
2. **找主隐喻**：从选题自己的世界里找一个东西贯穿全片（讲剪辑就用剪刀、胶片、厨房切菜；讲 app 就用手机、通知、开店）。再找 2–3 个**贯穿道具**（角落里一直在跳的计数器、反复出现的聊天气泡、真实的提交记录）。
3. **盘点真素材**：录屏、真实截图、真实数字、真实聊天、真实的错误信息。每个场景先问"有没有真东西可以放上来"。缺的列成清单给用户：用户补、导演去找免费可用的，还是用画的代替。
4. **找笑点**（创作者想要搞笑时）：从创作者这次做这件事的真实经历里找：谁问了什么、哪里出了错、哪里尴尬。框架可以夸张，事实（数字、日期、结果）必须是真的。

## 第三步：提三个档位，不要只给一个

在同一个真实细节上提三个方向：

| 档位 | 是什么 |
| --- | --- |
| **稳** | 选定风格里最稳妥的做法，一定不出错 |
| **大胆** | 换一个更有画面感的主隐喻，或者换一种构图（比如背景变成会动的"世界"） |
| **离谱** | 导演自己都犹豫要不要说出口的那个：荒诞的设定、不该用在这个话题上的形式、从错误的视角讲、创作者演一个角色 |

每个档位写：一句话概念 · 主隐喻 · 开场前 3 秒画面 · 高潮画面 · 结尾怎么呼应 · 大概多做多少工作。然后**说导演会选哪个、为什么**。

不要因为"不好做"就不提。先提，再说成本；用户宁愿否掉一个离谱的点子，也不想从来没听到过。用户说"再离谱一点""太正经了""换个完全不一样的"时，不要在上一个方案上修修补补，扔掉重来。

## 第四步：写 VISUAL.md

用户选定方向之后，写成这样一份方案：

```markdown
# 视觉方案

## 概念
一句话概念 / 主隐喻 / 贯穿道具 / 选定风格 + 动作清单（引用 STYLE-SHEET.md）

## 前 10 秒（逐拍）
| 时间 | 说的话 | 画面 | 动作（落在哪个词） |
| 0–2s | ... | ... | ... |
| 2–5s | ... | ... | ... |
| 5–10s | ... | ... | ... |
检查：2 秒内看到具体结果或问题 · 5 秒内观众知道跟自己有关 · 10 秒内有一个正文会兑现的小承诺

## 逐句分镜
| # | 文案 | 节拍 | 演法（隐喻/镜头/构图/节奏） | 动作 → 落在哪个词 | 真素材 | 声音 |

## 力度曲线
哪一两处用大演法（钩子、70–85% 的高潮），其余哪里安静。

## 结尾
怎么回到开头的主隐喻 / 贯穿道具。

## 素材清单
已有 / 要用户补 / 要去找（注明授权）/ 要画
```

## 导演的标准：不无聊的底线

方案交出去之前，逐条过一遍。任何一条不过，改了再交。

**开场**
- [ ] 第一秒就有一个"响"的动作，不是第五秒。开场直接是结果或问题，不是自我介绍。
- [ ] 出镜的视频里，背景是演员：说一句话，人身后的整个世界换一次（真实的页面、正在被填满的格子、滚动的真实文件名），新世界从人身后"长"出来。
- [ ] 钩子过后要安静下来，正文每一拍只有一处强调。

**密度与节奏**
- [ ] 每一句都有画面回应，每条字幕开始后 0.7 秒内有变化，没有 3 秒以上的死段。
- [ ] 相邻两段至少换了两个旋钮（隐喻、镜头、构图、节奏），每种演法全片最多用一次。
- [ ] 大演法只有一两个，放在钩子和 70–85% 的高潮。高潮前留一拍安静。

**好懂**
- [ ] 主隐喻 0.5 秒能认出来，并且在开头、每次转折、结尾都出现。
- [ ] 能演出来的不写出来（"赚到钱了" → 硬币堆起来，而不是打一行字）。
- [ ] 竖着拿手机看横屏视频也读得清：字够大，一屏一件事，不放整段文字。

**真实**
- [ ] 真素材优先。讲具体工具时用真实屏幕：先看整页 → 推近到操作的地方 → 光标点击 → 圈出结果。
- [ ] 说到哪画到哪：旁白念到屏幕上的哪句话，那句话就在那一刻被放大镜放大、高亮或画线。
- [ ] 截图里的网址、账号名、头像打码。
- [ ] 数字、日期、结果全部是真的；不知道的写"待填"，不编。

**有意思**（创作者想要搞笑时）
- [ ] 前 10 秒有一个笑点，每章有一个，结尾有一个呼应。
- [ ] 笑点落在创作者自己或情境上，不落在观众身上，不用刻板印象。
- [ ] 方案里至少有一处让人意外的画面（离谱档的点子，哪怕只用一小段）。

**人是主角**（出镜时）
- [ ] 东西从人身后长出来、落在手里、出现在头顶，而不是人在一边、PPT 在另一边。

**演示段落**
- [ ] 演示一个产品或流程时，按音乐写节拍表：定 BPM，用"第几拍"而不是秒数写每个动作，最大的动作放在 drop 上，结尾留一拍安静。

## 第五步：先给看，再开工

- 按 SKILL.md 的风格闸门，先做两三张真实风格帧（开场一张、正文一张、转场一张）或一个可以播放的开场预览，给用户确认。
- 附一张"继续做的成本"表：剩什么、各要多久。
- 用户确认之后，才交给 HyperFrames 那一步实现。

## 交给 HyperFrames 之后

- 实现的 agent 照 VISUAL.md 做，不自己改设计。做不出来或者效果不好，回到导演这一步改方案，并告诉用户改了什么。
- 预览做出来以后，导演再看一遍（**导演验片**）：抽帧拼成联系表，逐句对照 VISUAL.md，查密度、查"不无聊的底线"，把问题列成清单交给实现的 agent。
- 用户认可的新演法和新动作，补进 STYLE-SHEET.md 的动作清单和 staging.md 的节拍表，下次直接用。
